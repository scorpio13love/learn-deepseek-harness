DSH 运行时知识图谱

不是课程目录。每个节点都是一道会被追问的题；答案落到 DSH 的边界、事件和失败语义。

控制平面

turn、step、request 三者的边界是什么？

turn 是一次任务唤醒，从 turn/start 到 turn/end；step 是一次模型请求及其工具执行；request 是一次具体 Provider 调用。Turn 绑定用户意图与总预算，Step 绑定上下文与工具批次，Request 绑定路由、超时、重试与用量。

为什么模型请求必须从日志派生，而不是 loop 自己维护 messages？

因为恢复、fork、审计和压缩都要求“模型当时看到了什么”可解释。请求从 deriveMessages() 生成，日志里没有的东西不会出现在请求里；这也阻止了发送前偷偷塞提示词。

取消为什么不是回滚？

取消只是协作式停止：通知模型流和工具停止，但已经写入文件、数据库或远端的副作用不能撤销。系统只能把取消记录成事实，再由恢复策略决定补偿、继续还是结束。

失败事实和重试策略为什么要分开？

适配器只负责把 401/429/超时/断流归一化成稳定 failure；是否重试、等待多久、换不换路由，是 Agent 层或策略插件的决定。混在一起会让 adapter 擅自重复有成本的请求。

为什么 Agent Loop 本身也可以替换？

Loop 是控制平面，不是不可替换的特权内核。替代实现只要继续遵守日志、取消、工具结果和请求重建等契约，就可以换调度策略；不能遵守契约的实现，即使同名也不再是可恢复的 DSH Agent。

事实与上下文

为什么使用 append-only Session Log，而不是 messages 数组？

messages 只告诉你现在是什么，不能解释用户何时插话、模型何时请求工具、审批是否拒绝、进程是超时还是取消。Session Log 保存带 seq 的类型化事件，模型历史、UI、恢复、fork、审计都是它的投影。

surface 和 messages 数组有什么区别？

surface 是“当前模型视图”的 seq 列表，不是另一份可变消息。普通消息 append，压缩时用 replace 遮蔽旧段；deriveMessages() 按 surface 投影出模型历史。原始事件仍在日志里。

surface replace 和删除事件有什么区别？

replace 只发布一个新的视图节点，让旧 surface 被摘要遮蔽；旧事件不删除，sourceEventSeqs 记录它替换了哪些事实。删除会破坏回放、审计和 fork；replace 不会。

上下文压缩和简单截断的区别是什么？

截断按长度丢弃历史，可能连目标、约束、未完成调用和失败原因一起删。压缩把上下文当工作集：先 prune 语义密度低的工具结果，再摘要旧段落，并保留目标、约束、未完成动作和证据来源。

fork 为什么要选稳定前缀？

fork 复制一段连续事件作为新会话的过去；边界必须落在没有开放 Turn 的稳定位置。若在 turn 执行中切，会得到悬空历史，子会话无法解释“当时是否还有工具没结算”。

工具与权限

一个工具为什么有模型面、执行面、投影面？

模型面是名称、说明和参数 Schema；执行面是参数校验、取消和真实副作用；投影面把规范值变成模型内容和 UI 展示。三者混在一起，执行器元数据或 UI 结构会泄漏给模型。

guard 为什么只能单调收紧？

前置 waterfall 的执行顺序可能变化；若 guard 能返回 allow，后注册插件就可能推翻前面的拒绝。单调 guard 只返回拒绝理由或不做决定，新增规则只会缩小权限。

审批为什么必须 fail closed？

审批服务不可用、超时、回调抛错或用户直接关窗时，默认放行会把教学 demo 变成真实事故。审批请求还必须绑定工具、参数摘要、调用者和有效期，重试同一动作不能复用上一次的允许。

工具并发为什么默认独占？

一次模型回复可能请求多个工具；只有工具显式声明当前参数可并发，调用才进入 parallel 组。遗漏、异常或非 true 都按 exclusive 处理，形成顺序屏障，避免写文件、Shell 或共享状态被盲目并发。

为什么规范值、模型内容、UI 展示要分层？

execute 返回可校验的规范 JSON 值；output.render 把它投影成模型可见的 ContentBlock；presentationMeta 只服务 UI。这样 schema 校验、模型上下文和回放卡片不会互相污染。

组合与生命周期

Context 和 inject 解决什么问题？

Context 让消费方按稳定服务键取能力，而不是 import 具体实现；inject 把启动顺序变成依赖关系：依赖未满足就等待，提供方出现后激活，提供方离开后相关分支停下。

Fiber 和 effect 为什么是插件系统的核心？

插件注册服务、监听器、定时器都会改变进程。effect 给每个副作用一个归属，Fiber 在卸载时逆序撤销；没有它，HMR 只是替换文件，旧监听器和连接会泄漏。

Bundle、Profile、Patch 各管什么？

Bundle 分发一组可共同安装的插件行；Profile 定义 Web/headless/定制产品的有序配方；Patch 在明确层级覆盖或插入条目。把三者混在一个文件里也能启动，但无法判断变化该跟着产品、机器还是一次运行。

一个完整 Seam 有哪三个角色？

Service Definition 定义稳定契约，Provider 实现契约，Consumer 只依赖契约。消费者绕过 seam 直接访问本地实现时，替换 provider 只存在于配置表面，执行环境不会真正迁移。

HMR 为什么不能等于“重启插件”？

HMR 要卸载旧 Fiber、撤销 effect、激活新 Fiber，并处理失败回滚。它不会自动迁移插件持有的内存状态，也不能撤销已经提交到外部系统的副作用；这些仍要单独设计。

执行边界

浏览器工具为什么是回合制，而不是 RPC？

页面会在动作后变化：read 得到文本和 ref 表，click(ref) 必须返回新快照。模型下一步要用新 ref，而不是复用旧引用；否则点击后的页面状态无法解释。

CUA 的 dispatched 和 verified 有什么区别？

dispatched 只表示动作已派发给原生层；verified 表示 UI 真的变了。CUA 只能可靠地确认前者，所以动作通常返回 dispatched:true、verified:false，要求下一步重新截图观测。

PTC 是沙箱吗？

不是。PTC 把一组工具压缩成可组合的程序接口，提高表达密度，但程序仍是不可信输入。子调用必须重新进入普通 Tool Pipeline；CPU、时间、输出、进程和网络边界要由 runtime/sandbox 提供。

MCP 为什么不修改 loop？

MCP client 在 provider 侧发现工具、发起 JSON-RPC、把结果翻成普通 tool/result。loop 只看到 tool/call 和 tool/result，所以新增外部工具不需要改控制流；名字加 mcp__ 前缀只是避免冲突。

Subagent 的预算为什么在 manager 层检查？

子 agent 会放大权限、会话、并发和失败传播。maxDepth/maxActive 必须在创建 child 之前检查；只写在工具描述里，模型可以忽略或误解，运行时却已经创建了半成品。

质量与宿主

客户端为什么不自己 fold 事件？

多个客户端各自 fold 会得到不同结果，断线重连还可能把已结束的工具卡变回 running。host 用 projection 计算一次快照和增量，客户端只按 seq 渲染；projection 是纯函数，实时 UI 和回放都调用它。

SDK 为什么走 JSON-RPC / stdio，而不是嵌 loop？

编辑器、CI 和其他进程需要稳定边界，而不是共享内存。SDK 把 session/create、prompt、session/event 暴露为协议；服务端仍跑同一套 loop、日志和策略，客户端只消费事件。

record/replay 为什么不能只存最终文本？

只看最终文本无法解释工具调用、审批、失败和取消。record 保存事件与 assistant chunk；replay 用同一 loop 和记录重放，不请求模型，因此能复现同一失败并做 snapshot diff。

Eval 为什么需要故障矩阵？

只测成功路径无法知道 429、超时、断流、工具错误时系统怎么收口。固定 scenario 和 seed，逐格注入故障，报告必须说明哪一格失败、是否重试、turn 如何结束，而不是把失败包装成成功。

安全边界为什么不能交给模型？

模型会犯错，Prompt 会漂移，间接内容还可能注入指令。Approval、sandbox、凭据和审计属于策略平面，必须在运行时强制；策略解析失败要 fail closed，不能静默退回更宽权限。
